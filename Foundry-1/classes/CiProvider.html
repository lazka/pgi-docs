Foundry.CiProviderClass

Extension point for continuous integration implementations.

Providers discover pipelines for a project and create asynchronous [class`Foundry`.CiRun] objects for jobs and interactive job shells. Provider implementations should perform blocking work in fibers on a worker scheduler and use libdex asynchronous I/O helpers where available.

Loading a provider must remain passive. Providers should defer pipeline discovery and remote access until [method`Foundry`.CiProvider.list_pipelines] is called by an explicit consumer action.

Added in version 1.2.

invalidate()¶

Notifies the CI manager that the provider’s pipelines have changed.

Added in version 1.2.

a [class`Dex`.Future] that resolves to a [iface`Gio`.ListModel] of [class`Foundry`.CiPipeline] or rejects with error

Return type:

Dex.Future

Lists the pipelines available for the current project.

This is active discovery and may access remote resources. UI consumers should call this only in response to an explicit user action.

run(pipeline, job_ids, options)¶
Parameters:

  • pipeline (Foundry.CiPipeline) – a pipeline created by self

  • job_ids ([str] or None) – job identifiers, or None

  • options (Foundry.CiRunOptions) – options for the run

Returns:

a [class`Dex`.Future] that resolves to a [class`Foundry`.CiRun] or rejects with error

Return type:

Dex.Future

Starts a local pipeline run. If job_ids is None or empty, the provider runs the jobs selected by its pipeline rules. The run is exposed through the context’s [class`Foundry`.OperationManager] until it completes or is cancelled.
